Background

What Is 5G?

Definition

5G is the fifth generation of mobile networks. It enables communication with high speed, low latency, and massive connectivity between users, devices, and digital services.

Simple idea

It is not only for smartphones. 5G also connects cars, factories, homes, hospitals, and IoT systems to intelligent online services.

Core Focus

What Is the 5G Core?

Definition

The 5G Core is the central part of the network. It manages users, sessions, mobility, routing, authentication, and communication with external services.

Where it is deployed

In real environments, the 5G Core is deployed in operator data centers, private cloud platforms, or public cloud infrastructure.

Say this: “My project focuses specifically on the 5G Core because that is where service logic and API communication happen.”
Inside the Core

5G Core as Microservices

The 5G Core is not one monolithic system. It is composed of many independent Network Functions that behave like modern microservices and communicate through APIs.

AMFUser access and mobility
SMFSession creation and control
UPFUser traffic forwarding
NRFService discovery registry
AUSFAuthentication
UDMSubscriber data
NSSFNetwork slice selection
NEFNetwork exposure and diagnostics
Say this: “This is the key transition point in the presentation: once we view the core as microservices, API security becomes essential.”
Interfaces

Why Service-Based Interfaces Matter

Service-Based Interfaces

  • Used between core functions
  • HTTP/2 + JSON APIs
  • Examples: Namf, Nsmf, Nudm, Nnrf

Security consequence

  • Internal communication now looks like web API traffic
  • Input validation becomes critical
  • Authentication and authorization logic can be attacked
Say this: “The project is based on Service-Based Interfaces because they are the main API communication channels inside the 5G Core.”
Security Question

Is 5G Secure by Default?

Original assumption

  • Controlled telecom environments
  • Protected data centers
  • Strong network perimeter

Modern reality

  • Cloud deployments
  • Private 5G networks
  • University labs and research setups
  • Open-source platforms such as free5GC and Open5GS
Say this: “The 5G Core was originally designed for a controlled environment, but modern deployment models make the perimeter weaker and the API attack surface more exposed.”
Attack Surface

Why Could 5G Be Vulnerable?

Microservices

More services mean more internal communication paths and more code boundaries.

APIs

Network Functions exchange data through API endpoints, request bodies, tokens, and identifiers.

Deployment risks

Misconfiguration, weak validation, and limited telecom expertise can expose internal services.

Key idea

More flexibility means a larger attack surface. Security now depends not only on design, but also on implementation and deployment.

Threat Model

What Can an Attacker Do?

Potential attacker actions

  • Send malicious API requests
  • Exploit weak input validation
  • Try to impersonate a Network Function
  • Abuse object identifiers and service tokens

Potential targets

  • Private 5G deployments
  • University labs and research environments
  • Cloud deployments with misconfiguration
  • Development and testing environments
Say this: “This is where I move from telecom explanation to security analysis: the attacker does not need to break radio first. Weak APIs inside the core can already become the entry point.”

Conclusion

Final Conclusion

5G Core security is increasingly API security. Because the core uses microservices and Service-Based Interfaces, weak validation, weak trust assumptions, and weak authorization can become practical security problems.

What the project proves

  • 5G API risks can be demonstrated clearly
  • Injection and authorization flaws are understandable in a telecom context
  • Secure controls can be shown, not only described

Future work

  • Real integration with free5GC/Open5GS labs
  • mTLS or OAuth2 trust between services
  • PDF export of findings
  • More attack modules and fuzzing coverage
